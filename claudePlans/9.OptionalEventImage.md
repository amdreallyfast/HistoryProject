# 9. Optional EventImage (drop `[Required]` on the navigation)

TODO item: **Reconsider `[Required]` on `Event.EventImage`** (Refactors).

## Current state (verified 2026-11-25)

- `Event.EventImage` is `[Required] EventImage?`. EF maps it as a **required** FK: `Events.EventImageId uniqueidentifier NOT NULL`, `OnDelete(Cascade)` (image row deleted → events referencing it deleted).
- Every read endpoint does `.Include(x => x.EventImage)`, which is an **INNER JOIN** for a required navigation. An event with no image row would disappear from all of them.
- Workaround in place: `Create` does `e.EventImage ??= new EventImage { ImageBinary = [] }`, so "no image" is stored as an **empty-bytes image row**. Image sharing (claudePlans/8) matches that row by MD5 like any other image, so each event chain with no image shares one empty row.
- The frontend always sends a wrapper: `{ Id, ImageBinary: "" }`, even when there's no image or when it sends `ExistingImageId`.
- Already null-safe: `backendToFrontend` (`e.EventImage?.Id ?? null`), `useEventImageDataUrl` (doesn't fetch when `imageId` is null), and `Delete` (`if (rev.EventImage is not null)`).

## ⚠ Design change (needs your OK)

**"No image" changes from "an image row with empty bytes" to "no image row at all" (`EventImageId = NULL`).**

Impact:
- Schema: `EventImageId` becomes nullable. A migration is needed, and prod gets it by hand on the next release.
- Existing data: the migration converts existing empty-bytes rows to `NULL` and deletes those rows. Real images are untouched.
- API contract: an imageless event comes back with `"EventImage": null` instead of `{ Id, ImageBinary: "" }`. `CreatedRevision.EventImageId` becomes nullable. The frontend already handles both.
- Delete behavior: the image→event FK changes from **Cascade** to **no action**, which is EF's default for an optional FK. Deleting an image row should never delete events, and the only place images are deleted (`Delete`) removes the events itself first. This also removes a dangerous cascade that image sharing made easy to trigger.
- **Release-ordering hazard:** the new backend code writes `NULL` into a column that prod still has as `NOT NULL` until the migration runs. Prod must be migrated in the same release, which the CLAUDE.md release checklist already requires. The test environment auto-migrates.

## Tags / Sources (reassessed, recommend no change)

Both are **collection** navigations. `[Required]` on a collection doesn't make EF use INNER JOINs. The FK lives on the child row (`EventSource.EventId`) or in the `EventTag` join table, and an empty collection just loads as `[]`. There's no hazard here. `[Required]` only rejects a `null` list, which is a reasonable contract (send `[]`), and the frontend always does. Instead of assuming, step 1 adds a test that confirms an event with empty `Tags` and `Sources` reads back from every endpoint.

## Steps

1. **Pin current behavior with tests (backend).** Tests that: an event with empty Tags/Sources is readable everywhere. Plus an HTTP-level test (`WebApplicationFactory`) showing whether a payload with *no* `EventImage` currently gets 400 from `[ApiController]` model validation. Existing controller-level tests bypass model validation, and the controller comment says a null wrapper is accepted, so this resolves the contradiction with the TODO text.
2. **Backend model + migration.**
   - `Event.EventImage`: drop `[Required]`. Configure in `DbContext` as optional with `DeleteBehavior.ClientSetNull`.
   - `dotnet ef migrations add OptionalEventImage`. Then hand-add the data step after the column becomes nullable: point events with empty images at `NULL`, then delete the empty-bytes `Images` rows.
   - Read the generated SQL (the index and FK on `EventImageId` get dropped and recreated).
3. **Backend controller.**
   - `Create`: remove the `??=` workaround. Treat a null wrapper *or* empty `ImageBinary` as "no image" (store `NULL`, so old clients still sending `""` keep working). `chainImages` skips null image IDs. Return a nullable `EventImageId`.
   - `GetAllRevisions`: map to `EF.Property<Guid?>`, leaving `EventImage = null` when there's no image.
   - `GetImage` keeps its 204 path for safety.
   - Update the existing tests (CreateIdentity no-image test, ImageSharing) to the new contract. Add: "no image" across revisions stays `NULL` and doesn't create image rows.
4. **Frontend.** `frontendToBackend` sends no `EventImage` when there's no image. It sends `ExistingImageId` without the dummy wrapper. Update the mapper unit tests, the Playwright fixtures/mocks (add an imageless event with `EventImage: null`), and the comments that say the wrapper is required.
5. **Live E2E seed.** Drop the always-send-wrapper workaround in `LiveE2ETests` if one exists.
6. **Docs.** DESIGN.md (no-image representation, delete behavior), the TODO item, and the CLAUDE.md data-model line if needed.
7. **PR into `test`**, merge after checks pass. You test on the test site: create an event with no image, one with an image, then edit each with and without changing the image.

Prod migration (on the next release, not part of this PR): migration precondition check is a read-only count of empty-image rows, `SELECT COUNT(*) FROM Images WHERE DATALENGTH(ImageBinary) = 0;`. The release goes in the usual checklist order.
