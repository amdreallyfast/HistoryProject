## Goal

Add Playwright for end-to-end testing of the React + Vite frontend. Phase 1 covers:
1. Installing and configuring Playwright inside `npmfrontend/`
2. Writing smoke tests for page load and the Three.js canvas
3. Writing search-flow tests with mocked API calls (no dependency on live Azure backend)

## Installation

Run from `npmfrontend/`:

```bash
npm init playwright@latest
```

When prompted:
- Language: **TypeScript**
- Test directory: **tests**
- Add GitHub Actions workflow: **Yes** (review before committing — see GitHub Actions section below)
- Install browsers: **Yes** (at minimum Chromium)

## Configuration

Replace the generated `npmfrontend/playwright.config.ts` with:

```ts
import { defineConfig, devices } from '@playwright/test'

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  reporter: 'html',
  use: {
    baseURL: 'http://localhost:5173',
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:5173',
    reuseExistingServer: !process.env.CI,
  },
})
```

`npm run dev` uses `.env.development`, which sets `VITE_API_BASE_URL=https://localhost:7121`.
All API calls are mocked via `page.route()`, so the backend does not need to be running.

## API Mocking Strategy

The one API endpoint used by the search flow is:

```
GET https://localhost:7121/api/HistoricalEvent/GetFirst100
```

This is called by `src/api/historyEventApi.js:getFirst100()` via a plain `fetch()`. Playwright
intercepts at the network layer, so one `page.route()` covers every call through that function:

```ts
await page.route('**/api/HistoricalEvent/GetFirst100', async route => {
  await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify(fixtureEvents),
  })
})
```

## data-testid Strategy

Add `data-testid` only where role/label selectors are ambiguous. Candidates:

| Element | File | Attribute |
|---|---|---|
| Search text input | `SearchSectionMain.jsx` | `data-testid="search-input"` |
| Search submit button | `SearchSectionMain.jsx` | `data-testid="search-button"` |
| Each result item button | `SearchSectionMain.jsx` | `data-testid="search-result-item"` |
| Event title in details | `DisplayEventHeader.jsx` | `data-testid="details-event-title"` |

Use `page.getByRole()` and `page.getByLabel()` first; add `data-testid` only if those are
insufficient.

## Tests to Implement

### `tests/smoke.spec.ts` — page load and canvas

```ts
import { test, expect } from '@playwright/test'

test('page loads', async ({ page }) => {
  await page.goto('/')
  await expect(page).toHaveTitle(/History/i)
})

test('Three.js canvas is visible', async ({ page }) => {
  await page.goto('/')
  await expect(page.locator('canvas')).toBeVisible()
})
```

### `tests/search.spec.ts` — search flow

Cover these cases (mock `GetFirst100` in a `beforeEach`):

1. **Search form is visible on load** — assert the search input and button are visible
2. **Search returns results** — click the search button, await result items appearing
3. **Empty search does nothing harmful** — submit with empty input; the current behavior loads
   all 100 events, so assert results appear and the page does not crash
4. **Result items show the event title** — assert fixture title text is visible in a result item
5. **Clicking a result selects the event** — click a result, assert the details section shows
   the fixture event title (via `data-testid="details-event-title"`)

Example structure:

```ts
import { test, expect } from '@playwright/test'
import fixtureEvents from './fixtures/events.json'

test.beforeEach(async ({ page }) => {
  await page.route('**/api/HistoricalEvent/GetFirst100', async route => {
    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify(fixtureEvents),
    })
  })
  await page.goto('/')
})

test('search form is visible', async ({ page }) => {
  await expect(page.getByTestId('search-input')).toBeVisible()
  await expect(page.getByTestId('search-button')).toBeVisible()
})

test('search returns results', async ({ page }) => {
  await page.getByTestId('search-button').click()
  await expect(page.getByTestId('search-result-item').first()).toBeVisible()
})

test('result items show event title', async ({ page }) => {
  await page.getByTestId('search-button').click()
  await expect(page.getByText('Test Event One')).toBeVisible()
})

test('clicking a result shows event in details', async ({ page }) => {
  await page.getByTestId('search-button').click()
  await page.getByTestId('search-result-item').first().click()
  await expect(page.getByTestId('details-event-title')).toHaveText('Test Event One')
})
```

## GitHub Actions Consideration

`npm init playwright@latest` generates `.github/workflows/playwright.yml`. Before committing,
review and adjust:

- The working directory: the generated workflow runs from the repo root; Playwright lives in
  `npmfrontend/`, so steps need `working-directory: npmfrontend` or explicit `cd` commands.
- Trigger branches: decide whether to run on `main`, `test`, or both. Recommendation: both,
  since the test branch is the active dev environment.
- The existing `deploy-backend.yml` is path-scoped to `WebAPI/**`; consider whether the
  Playwright workflow should also be path-scoped (e.g., `npmfrontend/**`) or run on all pushes.
- Browser caching: the generated workflow includes a cache step for Playwright browsers — keep it.

## Implementation Steps

1. Run `npm init playwright@latest` from `npmfrontend/`
2. Replace `playwright.config.ts` with the config above
3. Create `tests/fixtures/events.json` with the fixture data above (verify field names against
   `eventMapper.js:backendToFrontend` before committing)
4. Write `tests/smoke.spec.ts`
5. Run smoke tests: `npx playwright test tests/smoke.spec.ts` — all must pass before continuing
6. Add `data-testid` attributes to `SearchSectionMain.jsx` and `DisplayEventHeader.jsx`
7. Write `tests/search.spec.ts`
8. Run all tests: `npx playwright test` — fix any failures
9. Review and adjust the generated `.github/workflows/playwright.yml`
10. Commit

## Notes

- **React async rendering:** use `await expect(locator).toBeVisible()` rather than asserting
  immediately after a click — Redux state changes and React re-renders are async.
- **Redux internals:** assert on what the UI shows, not Redux state directly.
- **Backend not required:** `webServer.command` starts only the Vite dev server; all network
  calls are intercepted by `page.route()` before they reach `localhost:7121`.
- **Canvas testing:** for now just assert the canvas exists and is visible. Pixel-level or
  interaction testing of the Three.js globe is out of scope for this phase.
- **Import of JSON fixture:** TypeScript may require `"resolveJsonModule": true` in
  `tsconfig.json` to import the fixture file — check and add if missing.
